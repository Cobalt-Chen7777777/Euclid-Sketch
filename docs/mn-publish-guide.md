# 如何把插件发布到 MarginNote 社区 / 进入 MN 插件库

> 适用：Euclid Sketch 0.2.0（场景插件）
> 结论先行：MN 没有「网页表单直接上传」的商店入口，官方路径是 **① 社区发帖 + ② 私信管理员做签名认证**。
> 适用范围：**正式版**。beta 版只发社区帖，不提交插件库（官方库只收稳定版）。

---

## 一、准备材料（现在都已就绪）

| 材料 | 位置 |
|---|---|
| 插件包 `.mnaddon` | 本项目 `release/Euclid Sketch-0.2.0.mnaddon`（或 GitHub 仓库 `release/` 目录） |
| 模板包 `.mntemplate` | 同上 |
| 更新日志 / 帖子正文 | `docs/mn-release-notes-0.2.0.md`（直接复制） |
| 功能截图（建议 3–5 张） | 画布作图、插入卡片图、复制到批注、计算器小窗 |
| 图标 | `dist/icon.png`（投稿帖子时可用） |

> 截图建议用 iPad 真机截：① 在题目卡上画辅助线 ② 函数面板画曲线 ③ 复制图片粘贴进批注后的卡片样子。这三张最能说明价值。

## 二、发帖到中文社区（5 分钟）

1. 打开 https://bbs.marginnote.com.cn ，用 MN 账号或邮箱登录
2. 进入「插件」板块（分类列表里找「插件 / Add-ons」），点「新建话题」
3. 按 `docs/mn-release-notes-0.2.0.md` 的内容粘贴：
   - 标题照抄
   - 正文：功能 → 更新日志 → 安装 → 反馈
   - 在每个功能段落下插入对应截图
4. 发布后把帖子链接记下来（后续版本更新在**同一帖**里回复「v0.2.1 更新」即可，不要另开新帖，社区习惯跟帖更新）

## 三、申请签名认证（进 MN 插件库的关键一步）

MN 官方对插件做签名认证，认证过的插件会出现在 MN 内置插件库、显示认证标识，用户可直接在 MN 里搜索安装。

1. 在社区私信管理员 **@Randa**（公告帖：https://bbs.marginnote.com.cn/t/topic/65971 ）
2. 私信内容用 `docs/mn-release-notes-0.2.0.md` 末尾的「私信 @Randa 用的简短说明」
3. **附上两个包**（`.mnaddon` + `.mntemplate` 作为附件上传）
4. 等待回复认证结果（一般几个工作日）；被要求修改时按提示调整后重新发送

注意事项（官方明确要求）：
- 开发者**不要**在插件运行过程中修改插件自身目录下的文件——会导致认证失效。
  Euclid Sketch 不写自身目录（设置存 localStorage、导图走用户操作），符合要求。
- 备选联系方式：邮件 randa@marginnote.com

## 四、认证之后

- 插件会进入 MN 的插件库，用户在 **设置 → 插件** 里可直接搜索安装
- 版本更新流程：本地打新版本包 → 在社区原帖回复更新日志 → 私信 @Randa 提交新版本包复核
- 记住：**MN 对同版本包跳过安装**，每次发版必须递增 `mnaddon.json` 里的 `version`

## 五、常见问题

**Q：必须认证吗？**
不必须。用户也能通过 GitHub / 社区附件下载 `.mnaddon` 手动导入（设置 → 插件 → 导入）。认证的意义是进内置插件库、有官方信任标识。

**Q：只发 GitHub 不发社区行不行？**
可以，但 MN 用户主要在社区活动，曝光和反馈都会少很多。建议社区主发、GitHub 作为下载与 issue 渠道。

**Q：更新日志要写多细？**
面向用户写「他能感知到什么」：新功能、修了什么毛病、快了多少。不要写内部实现（接口名、hook、memo 化这类留给我们自己的 CHANGELOG.md）。

**Q：帖子发在哪个板块最容易被人看到？**
「插件」板块 + 标题带【场景插件】前缀（区分老的经典插件），并在正文第一段就说清「解决什么问题」。
